games

Four TCGs, one binary. Each game gets its own importer, card database, and a card-detail renderer that lays out the stats that matter for that game.

  • Pokémon TCG TCGDex API · HP, attacks, abilities, weaknesses, retreat cost. alias: pokemon
  • Yu-Gi-Oh! YGOPRODeck API · ATK/DEF, levels, link markers, card text. alias: yugioh
  • Magic: The Gathering MTG API · mana cost, type line, power/toughness, loyalty. alias: mtg
  • One Piece OPTCG API · cost, power, counter, life, full effects. alias: onepiece

features

Built with Bubble Tea and an adaptive Catppuccin theme that follows your terminal — the palette this page uses. All data lives in a single SQLite file. Pure Go, no CGO, no external services.

collection tracking

Per-card quantities and set-completion grids colored by rarity.

price snapshots

TCGPlayer and Cardmarket prices, total value, and change history.

fuzzy search

Typo-tolerant search across name, number, rarity, and artist.

lists & wishlists

Unlimited named lists with color labels: wishlists, binders, trades.

deck builder

Build decks with format-aware validation when you save.

import & export

Live import queue; export to CSV, Text, or PTCGO; re-import from CSV.

modes

No accounts, no cloud, no browser. Run it on your laptop, or host it once and let the whole play group SSH in.

local — just you and a .db file

Launch the TUI directly. Your collection lives in a portable SQLite file next to the binary.

local
$ cardman serve
  • single-user, zero configuration
  • works offline after import
  • back up by copying one file
ssh — one host, many collectors

Serve CardMan over SSH. Every user logs in with their own account and gets an isolated collection.

server & client
# on the server
$ cardman serve-ssh
# from any machine
$ ssh -p 2222 you@your-server
  • multiple independent users
  • per-user settings stored in the db
  • docker-ready deployment

quick start

Grab a release binary for Linux, macOS (amd64/arm64), or Windows — or build from source with Go 1.25+. The build is pure Go, so there is no C toolchain to fight.

install & run 
# download a release (linux amd64 shown)
$ VERSION=v0.2.0
$ curl -L "https://github.com/laiambryant/tui-cardman/releases/download/${VERSION}/cardman_${VERSION}_linux-amd64.tar.gz" | tar xz
$ sudo mv cardman /usr/local/bin/

# set up the database and card data
$ cardman migrate
$ cardman import all pokemon

# launch
$ cardman serve
✓ cardman is running █
from source 
$ git clone https://github.com/laiambryant/tui-cardman.git
$ cd tui-cardman
$ make build
$ ./cardman serve
.env — all optional, defaults shown
DB_DSN       = file:cardman.db?_pragma=foreign_keys(1)
LOG_LEVEL    = INFO                    # DEBUG|INFO|WARN|ERROR
SSH_PORT     = 2222
SSH_HOST_KEY = ~/.ssh/cardman_host_key
API_KEY      =                         # tcgdex.dev key (optional)

commands

Everything the TUI does, the CLI does too — handy for scripts and cron jobs. <game> is one of pokemon, yugioh, mtg, onepiece.

commandwhat it does
setup
cardman migrateapply database migrations
cardman servelaunch the TUI (local mode)
cardman serve-sshstart the multi-user SSH server
import
cardman import list-sets <game>list available sets from the API
cardman import sets <game> <id…>import specific sets
cardman import all <game>import every set and card
cardman import new <game>import only new sets
browse
cardman cards list <game>list cards — --search, --json
cardman cards info <game> <set> <n>show one card's details
collection · decks · lists
cardman collection list | add | removemanage owned cards
cardman collection import | exportCSV in — CSV, Text, PTCGO out
cardman decks create | show | add-card | validatebuild and check decks
cardman decks exportCSV, Text, or PTCGO
cardman lists create | show | add-card | exportnamed lists — CSV or Text

Run any command with --help for the full flag reference.
